================================================================================

TEST_DESCRIBIR_SALA (opción 1)
├─ Función: void Describir_Sala(Partida *par)
├─ Qué testa: Mostrar la descripción de la sala actual

TEST_EXAMINAR (opción 2)
├─ Función: void Examinar(Partida *par)

├─ Por qué: El jugador necesita saber qué hay en la sala

TEST_INVENTARIO (opción 3)
├─ Función: void Inventario()
├─ Qué testa: Mostrar items del jugador
├─ Por qué: El jugador necesita ver qué lleva (máx 5 items)
└─ Resultado esperado: ✓ Muestra solo items en inventario

TEST_COGER_OBJETO (opción 4)

├─ Qué testa: Mover objeto de sala a inventario
├─ Por qué: El jugador puede recopilar objetos cruciales
└─ Resultado esperado: ✓ Items incrementados correctamente

TEST_SOLTAR_OBJETO (opción 5)
├─ Función: void SoltarObjeto(Objetos *obj, Jugadores *jug, Partida *par)

💡 EXPLICACIÓN DE CADA PASO
================================================================================

Cuando ejecutas un test, el módulo hace esto:

1. INICIALIZA permisos de prueba realistas:
   - Crea 3 salas (Entrada, Pasillo, Salida)
   - Crea 3 objetos (Llave, Linterna, Mapa)
   - Crea 2 conexiones entre salas (una abierta, una bloqueada)
   - Crea 1 puzle con solución "CASTILLO"
   - Crea 1 jugador con 1 ítem en inventario

2. EJECUTA la función de juego.c con esos datos

3. VERIFICA los resultados:
   - ¿Se actualizaron correctamente los datos?
   - ¿El funcionamiento es el esperado?
   - ¿Hay errores de lógica?

4. MUESTRA el resultado:
   - ✓ = Test pasó (todo bien)
   - ✗ = Error encontrado (algo no funciona)
   - ! = Advertencia (revisar)

================================================================================
🐛 CÓMO ENCONTRAR ERRORES
================================================================================

Los tests están diseñados para DETECTAR errores comunes:

ERROR TIPO 1: Punteros incorrectos
  Síntoma: "Segmentation fault"
  Causa: Puntero no inicializado, malloc() faltante
  Solución: Revisar todas las declaraciones de punteros

ERROR TIPO 2: Comparaciones incorrectas
  Síntoma: El test dice "Items no se incrementaron"
  Causa: Olvidó ++, --, o comparó incorrectamente
  Solución: Revisar operadores de incremento/decremento

ERROR TIPO 3: Lógica incorrecta
  Síntoma: El test pasa pero el comportamiento es raro
  Causa: Condiciones if incorrectas, bucles mal estructurados
  Solución: Agregar printf() para debug, rastrear el flujo

ERROR TIPO 4: Memoria
  Síntoma: realloc() falla o produce corrupción
  Causa: Tamaño incorrecto de malloc(), acceso fuera de rango
  Solución: Verificar índices y tamaños de arrays

🔧 PERSONALIZAR LOS TESTS
================================================================================

Puedes modificar los datos de prueba para probar diferentes casos:

Ejemplo: Cambiar el número de objetos
  En prueba_juego.c, busca:
    Objetos *objetos = (Objetos*) malloc(3 * sizeof(Objetos));
  Cambia "3" por otra cantidad
  Crea los nuevos objetos
  Recompila

Ejemplo: Cambiar la solución del puzle
  En prueba_juego.c, busca:
    strcpy(puzles[0].solucion_puzle, "CASTILLO");
  Cambia "CASTILLO" por otra palabra
  Actualiza test_resolver_puzle() también
  Recompila

Esto es útil para probar:
- Casos extremos (0 items, 5/5 items, etc.)
- Diferentes tipos de datos
- Errores potenciales

❓ PREGUNTAS FRECUENTES
================================================================================

P: ¿Por qué algunos tests no piden input como scanf()?
R: Los tests están AUTOMATIZADOS para reproducir fácilmente.
   Si necesitas input, modifica juego.c para agregar scanf()

P: ¿Puedo ejecutar solo un test?
R: Sí, selecciona 1-6 para tests individuales
   Selecciona 7 para todos a la vez

P: ¿Qué significa "localizacion_objeto == 0"?
R: 0 = objeto en inventario del jugador
   Otro número = ID de sala donde está el objeto

P: ¿Cómo sé si un test pasó?
R: Busca "✓ Test completado exitosamente" al final
   Si lo ves, el test pasó

P: ¿Puedo ver el código de un test?
R: Sí, abre prueba_juego.c y busca void test_*(). Está bien documentado.

P: ¿Qué hago si me encuentro "Segmentation fault"?
R: Hay un problema con punteros o memoria.
   1. Abre juego.c
   2. Verifica que ALL punteros están inicializados
   3. Verifica que todos malloc() tienen free()
   4. Usa valgrind si tienes (avanzado)

P: ¿Puedo usar este módulo en examen?
R: Sí, es para validar tu código, no para hacer trampa.
   Te ayuda a encontrar bugs rápidamente.
